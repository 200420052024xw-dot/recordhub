# Workflow1 异常流程与重评接口

> 策略总纲：**单点异常不再拖垮整天流程**——能跳过的跳过并标注，凡跳过/失败都记入当日
> 异常台账，并逐条即时通知管理员；组织级硬校验（部门无部长、人员缺直属评价人、角色链
> 不符）仍然拦截整天启动，防止评价归属出错。

## 1. 异常处理规则一览

| 异常 | 处理 | 标注位置 |
|---|---|---|
| 成员当日未提交日志 | 记录并跳过评价 | ① 成员日志文档写"未交工作日志"；② AI 评价表回写一行：`评价编号={日期}:MISSING:{人员编号}`、肯定/改进两列均写"未填写日志"、工作日志列留空 |
| 同一个人同日提交多条日志 | **只保留最后提交的一条**，更早的被取代 | 台账 `log:{编号}:superseded`；顺带保证问卷（被评价人+填写人）能唯一定位日志 |
| 日志缺提交时间/时间无法解析 | 按表格记录顺序（即填写顺序）取**上一条有时间的记录**的时间回填；开头缺失取下一条；全表无时间取当前时刻。落在目标日内就正常处理 | 台账 `log:{编号}:time-interpolated` |
| 日志提交人不在人员表 | 该条日志跳过（不评价、不写回、不进文档），其他人照常走完 | 台账 `log:{编号}:unknown-submitter`，通知里附姓名与原因 |
| 单条日志 LLM 重试耗尽失败 | 该条标"AI 生成失败"跳过，**全天继续**；文档中该日志显示"评价生成失败（管理员可调用重评接口补评）"；截止放行不阻塞 | 台账 `log:{编号}:ai-failed` |
| 截止时人工未评价 | 保留 AI 结果充当最终结果 | 文档标签显示"（AI·人工未评价）"，快照 `manual_skipped=true` |
| 某人缺 OpenID | 跳过与其相关的通知/评价行/报告索引行 | 台账 `person:{编号}:missing-open-id` 或 `report:{键}:missing-open-id` |
| 云文档被人工编辑（与快照不一致） | **以人工版本为准**，程序停止续写该文档，其余流程照常 | 台账 `doc:{键}:manual-edit` |
| 整表读取/批量写入网络失败 | 仍整天 FAILED（外部故障需重试，不算数据异常） | 工作流状态 `last_error` |

## 2. 异常台账与管理员通知

- 台账保存在当日状态文件 `data/state/workflows/YYYY-MM-DD.json` 的 `snapshot.issues`
  （幂等键 → 原因文本），同一天同一异常只记一次、只通知一次。
- 配置 `.env` 的 `RECORDHUB_ADMIN_OPEN_ID` 后，每出现一条新异常立即给该飞书账号发一条
  文本消息（【Workflow1 异常】+ 原因）；未配置则只记台账。通知发送失败不影响流程。
- 查询当日台账：

```
GET /admin/workflows/{YYYY-MM-DD}/issues
Authorization: Bearer <RECORDHUB_ADMIN_TOKEN>
```

```json
{"target_date": "2026-10-03",
 "issues": {"log:L2:ai-failed": "日志 L2 AI 评价生成失败（重试已耗尽）…"}}
```

## 3. 重评接口（只重评失败或未处理的日志）

```
POST /admin/workflows/{YYYY-MM-DD}/resume
Authorization: Bearer <RECORDHUB_ADMIN_TOKEN>
```

- 语义：把当日标记为"AI 生成失败"的日志重置后**只重跑这些失败项**（以及尚未处理过的
  日志）；已有 AI 结果的日志一律不动。
- **自动路径永不重评失败项**：每日定时任务、服务重启恢复、12:00 截止放行都不会再次
  调用 LLM 重跑失败日志；重评只能由本接口显式触发。
- 时机限制：
  - 在截止放行**之前**重评成功：新结果正常进入 AI 评价表与三级文档。
  - 在截止放行**之后**重评成功：补写 AI 评价表行与本地快照；**已生成的云文档不回补**
    （文档可能仍显示"评价生成失败"，需要完整文档时人工补一句或重建当日文档）。

## 4. 数据持久性口径（与人员管理接口的关系）

- 未交标注行、补评行都只写飞书表一次，之后靠评价编号幂等对账，重启/重跑不重复。
- 人员增删改查见 [人员管理接口文档](人员管理接口文档.md)：台账里的"提交人不在人员表"
  补录人员后，需要**重跑当日**（resume）才会把那条被跳过的日志纳入——日志读取只在快照
  构建时发生一次，已建快照不追加日志。
