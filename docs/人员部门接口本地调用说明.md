# 获取人员/部门接口 · 本地调用说明

对应接口:`GET /admin/organization/persons`(service/api.py),返回组织架构缓存中的全部人员和部门。

## 1. 前置条件

- `.env` 中必须配置 `RECORDHUB_ADMIN_TOKEN`,且**不能为空**。留空时接口直接返回 `503 Endpoint token is not configured`。
- 启动服务:

```bash
python main.py serve --host 127.0.0.1 --port 8000
```

看到日志 `service_started ...` 即表示服务已就绪(启动时会先刷新/加载组织架构缓存,可能需要几秒)。

## 2. 请求

| 项目 | 值 |
|---|---|
| 方法 | `GET` |
| URL | `http://127.0.0.1:8000/admin/organization/persons` |
| 请求头 | `Authorization: Bearer <你的RECORDHUB_ADMIN_TOKEN>` |
| Body | 无 |

## 3. WorkBuddy 配置方式

- Method 选 `GET`
- URL 填 `http://127.0.0.1:8000/admin/organization/persons`
- Headers 里加一行:
  - Key: `Authorization`
  - Value: `Bearer 你的TOKEN`(注意 `Bearer` 和 token 之间有一个空格)

> 如果 WorkBuddy 是跑在另一台机器/容器里,`127.0.0.1` 不通,需要改用本机局域网 IP,并用 `--host 0.0.0.0` 启动服务。

## 4. curl 等价命令

```bash
curl -s http://127.0.0.1:8000/admin/organization/persons \
  -H "Authorization: Bearer $RECORDHUB_ADMIN_TOKEN"
```

```json
{

  "anomalies": [],
  "persons": [
    {
      "person_id": "p_xxxxxxxx",
      "name": "张三",
      "role": "evaluator",
      "department_id": "od-xxxxx",
      "leader_id": "p_yyyyyyyy",
      "open_id": "ou_zzzzzzzz",
      "source_record_id": "recxxxxxx",
      "active": true
    }
  ],
  "departments": [
    {
      "department_id": "od-xxxxx",
      "name": "研发部",
      "minister_id": "p_yyyyyyyy",
      "source_record_id": "recxxxxxx",

```

字段定义见 schema/domain.py:13 的 `Person` 和 schema/domain.py:24 的 `Department`;除 `person_id`/`name`/`role` 外均可为 null。

## 6. 常见错误

| 状态码 | 含义 | 处理 |
|---|---|---|
| 401 `Invalid bearer token` | Token 不匹配 | 检查 Header 是否为 `Bearer <token>`,有无多余空格/引号 |
| 503 `Endpoint token is not configured` | `.env` 里 `RECORDHUB_ADMIN_TOKEN` 为空 | 配置后重启服务 |
| 连接被拒绝 | 服务未启动或端口不对 | 确认 `python main.py serve` 正在运行,默认端口 8000 |

## 7. 无鉴权的联通性自检

不配 Token 也可以先验证服务是否活着:

```
GET http://127.0.0.1:8000/health/live
```

返回 `{"status":"ok"}` 说明端口和服务都正常,问题出在鉴权配置上。
