# 四类人员职责与 Skill 清单

所有输出采用统一的 Markdown 记录结构。基层学生填写基础记录，骨干和部长在原记录上补充评价，各级汇总保留原始内容和评价来源。阶段分析也沿用统一结构，在“分析结果”中填写不同类别的结论，不强行把技术、课程或 idea 写成个人日志。

同一 Skill 首次出现时列出完整信息，后续注明“同上”。本文规定需求、数据格式和执行安排，尚不实现 Skill、Agent 或定时任务。

## 一、基层学生

| 要做什么 | 辅助 Skill | 输入 | 输出 | 输出格式 | 执行与确认 |
| --- | --- | --- | --- | --- | --- |
| 每日整理并提交自己的工作日志 | **S01 工作日志完善 Skill** | 本人当天的培训学习、任务工作、进展、心得反思和困难等原始记录；本人身份信息 | 基层学生每日工作日志 | 统一记录结构：填写姓名、人员编号、部门、角色、是否为骨干、时间、日志内容、成果出处（如有）；评价和分析部分暂为空 | 本人提供原始记录后调用，每日由本人确认并提交 |

日志内容包括“做了什么、具体进展、心得或反思、遇到的问题”。部门、人员编号等已知信息可由程序带入；Skill 帮助整理表达，不编造工作和反思。

## 二、骨干学生

| 要做什么 | 辅助 Skill | 输入 | 输出 | 输出格式 | 执行与确认 |
| --- | --- | --- | --- | --- | --- |
| 每日整理并提交自己的工作日志 | 同上（S01） | 同上，来自骨干本人 | 骨干学生每日工作日志 | 同上（S01） | 每日，由本人确认并提交 |
| 每日检查全部直属基层学生的前一日日志，评价内容、统计提交情况并总结工作 | **S02 前一日日志检查 Skill** | 直属基层学生名单、所有直属基层学生的前一日工作日志；材料由程序准备 | 基层学生前一日检查清单 | 统一记录结构：逐人保留基础记录，补充已交／未交、肯定之处、改进之处、评价人和来源；总体统计为应交人数、已交人数、未交人数；分析结果填写所有已交人员的工作总结 | 每日定时生成，由骨干确认 |

只区分“已交／未交”。肯定具体详实的工作及有新意的想法，改进建议指出可补充的工作细节、心得或反思。骨干自己的工作日志与直属基层学生检查清单分开保存。

## 三、部长

| 要做什么 | 辅助 Skill | 输入 | 输出 | 输出格式 | 执行与确认 |
| --- | --- | --- | --- | --- | --- |
| 每周整理并提交自己的工作日志 | 同上（S01） | 本人本周的工作、进展、心得反思和困难等原始记录；本人身份信息 | 部长每周工作日志 | 同上（S01），时间填写本周起止日期；角色为部长，是否为骨干填“不适用” | 每周，由部长本人确认并提交 |
| 每日检查全部直属骨干学生的前一日日志，评价内容、统计提交情况并总结工作 | 同上（S02） | 直属骨干学生名单、所有直属骨干学生的前一日工作日志；材料由程序准备 | 骨干学生前一日检查清单 | 同上（S02），评价对象为直属骨干 | 每日定时生成，由部长确认 |
| 汇总前一日本部门全部学生的检查情况 | **S03 学生每日检查总清单生成 Skill** | 骨干学生前一日检查清单，以及全部直属骨干提交的基层学生前一日检查清单 | 部门学生前一日检查总清单 | 同上（S02），合并本部门骨干和基层记录，保留已有评价及来源；程序重新核算统计，Skill 整理整体工作总结 | 每日执行，所需清单确认齐备后汇总，由部长确认 |
| 了解本部门各项工作的阶段进展和困难 | **S04 阶段工作进展汇总 Skill** | 程序已筛选的本部门学生检查记录及其材料范围说明 | 部门阶段工作进展汇总 | 统一记录结构；分析结果逐项填写：结果类别“工作进展”、工作事项、所属部门、参与者、当前进展、主要困难（如有）、来源记录编号 | 每三天自动生成一次，由部长确认 |
| 整理拟降级、拟奖励的骨干，以及拟退出、拟提拔的基层学生 | **S05 降级—奖励—退出—提拔名单生成 Skill** | 程序已筛选的本部门学生检查记录及其材料范围说明 | 降级—奖励—退出—提拔名单 | 同一结构；分析结果按“拟降级、拟奖励、拟退出、拟提拔”分组，每条填写姓名、人员编号、部门、建议理由、具体事实、来源记录编号 | 每月自动生成一次，由部长确认 |
| 发现本部门有潜力的想法 | **S06 idea 清单生成 Skill** | 程序已筛选的本部门学生检查记录及其材料范围说明 | idea 清单 | 同一结构；分析结果每条填写：结果类别“idea”、idea 内容、提出者及人员编号、来源部门、来源记录编号 | 每月自动生成一次，由部长确认 |
| 组织学生例会，提前筛查有困难、有兴趣、有好想法或有培养潜力的学生 | **S07 学生例会重点人员筛查 Skill** | 程序已筛选的本部门学生检查记录及其材料范围说明 | 重点谈话学生清单 | 同一结构；分析结果每条填写：结果类别“重点谈话”、姓名、人员编号、部门、关注类别、具体依据、来源记录编号。关注类别包括思想或态度沟通、持续困难、兴趣、好 idea、培养潜力，可多选 | 每月自动筛查一次，由部长确认；例会暂沿用每周组织，会前可手动重跑 |

阶段工作包含培训、工程、论文、专利、竞赛、本科及研究生毕业论文等。人员名单是建议，不自动执行人员变动。部长汇总基层记录时保留骨干的评价；需要补充意见时另加评价条目，不覆盖骨干原意见。

| --- | --- | --- | --- | --- | --- |

| 了解所有部门各项工作的阶段进展和困难 | 同上（S04） | 程序已筛选的全团队学生检查记录及其材料范围说明 | 团队阶段工作进展汇总 | 同上（S04） | 每三天自动生成一次，由团队负责人确认 |

| 面向所有部门组织学生例会，提前筛查重点谈话学生 | 同上（S07） | 同上，范围为全团队 | 重点谈话学生清单（全团队） | 同上（S07） | 每月自动筛查一次，由团队负责人确认；例会暂沿用每周组织，会前可手动重跑 |
| 提炼可供各部门复用的工程技术和科研技术 | **S08 公共技术提炼 Skill** | 程序已筛选的全团队学生检查记录及其材料范围说明 | 公共技术提炼与入库建议清单 | 同一结构；分析结果每条填写：结果类别“公共技术”、技术名称、工程／科研类别、解决的问题、来源部门、贡献者、已有成果及出处、适用场景、入库或补充建议、待完善事项、来源记录编号 | 每周自动生成一次，由团队负责人确认 |

## 五、统一输出结构与逐层补充规则

### 1. 所有输出使用同一文档结构

每份 Markdown 文件包含文件信息和三个正文部分：逐人记录、总体统计、分析结果。各 Skill 按职责填写相关部分；不适用的部分标记“不适用”，不为了填满模板生成无关内容。

| 组成 | 统一字段 | 谁填写或生成 |
| --- | --- | --- |
| 文件信息 | 文件编号、材料类型、覆盖范围、起止日期、生成时间、执行部门、Skill 编号及版本、确认状态、确认人、来源文件 | 程序自动带入，确认人完成确认 |
| 第一部分：逐人记录 | 记录编号、人员编号、姓名、部门编号与名称、角色、是否为骨干、时间、日志内容、成果出处、已交／未交、评价列表、来源 | 本人提供基础内容；上级在评价列表中补充 |
| 评价列表 | 评价人、评价人角色、评价时间、肯定之处、改进之处 | S02 生成建议，由骨干或部长确认；有多次评价时保留多条 |
| 第二部分：总体统计 | 覆盖日期、应交人数、已交人数、未交人数；多日分析需要时增加应交人次、已交人次、未交人次 | 程序计算；个人日志等不需要统计的材料填“不适用” |
| 第三部分：分析结果 | 结果编号、结果类别、主题或对象、涉及人员及部门、具体内容、依据与来源记录编号 | S02、S03 填写工作总结；S04—S09 填写各自分析条目 |

“时间”指实际工作日期或工作起止日期；生成时间、评价时间分别记录。基层、骨干日志使用单日日期，部长周日志使用起止日期。

“是否为骨干”只表达学生身份：基层为否、骨干为是；部长和团队负责人为不适用，另用“角色”区分。各级评价不会改变被评价人的身份。

### 2. 基础记录逐级传递

| 环节 | 对基础记录的处理 |
| --- | --- |
| 基层学生提交 | 填写自己的身份、部门、日志内容、时间；评价部分为空 |
| 骨干检查基层 | 原日志保留，新增提交状态、肯定之处和改进之处；汇总统计与工作总结 |
| 部长检查骨干 | 对骨干自己的日志作同样处理 |
| 部长汇总全部学生 | 合并两类检查清单；原始内容和已有评价保留，需要补充评价时追加条目 |
| 团队负责人汇总 | 合并各部门总清单，保留人员、部门、原始记录和评价出处 |
| 各项阶段分析 | 引用程序筛选后的原记录，另行生成分析结果；一条结论可引用多个人、多个日期的记录 |

同一原始日志沿层级传递时保留记录编号。检查清单和分析报告有各自的文件编号；不因反复汇总把同一日志视为新工作。文件可复制原文以便阅读，但以原记录编号与版本追溯出处。

### 3. Markdown 模板

以下尖括号内容是待填占位符，不是真实数据。日志内容较长时按人员分段保存，不把长文硬塞进表格。

```markdown
# <材料名称>

-文件编号：<唯一编号>
-材料类型：<个人日志／检查清单／检查总清单／阶段分析>
-覆盖范围：<个人／直属人员／部门／全团队>
-起止日期：<开始日期> 至 <结束日期>
-生成时间：<日期时间>
-执行部门：<部门编号>
-Skill及版本：<S编号、版本>
-确认状态：<待确认／已确认>
-确认人：<姓名、人员编号>
-来源文件：<编号列表>

## 第一部分：逐人记录

### <记录编号>

-人员编号：<人员编号>
-姓名：<姓名>
-所属部门：<部门编号、名称>
-角色：<基层学生／骨干学生／部长／团队负责人>
-是否为骨干：<是／否／不适用>
-时间：<实际工作日期或起止日期>
-提交情况：<已交／未交>
-成果出处：<有则填写>
-来源：<原日志编号及版本；无则注明>

#### 日志内容
<学习或工作事项、具体进展、心得反思、困难>

#### 评价
-评价人：<姓名、角色>
-评价时间：<日期时间>
-肯定之处：<具体表现>
-改进之处：<具体建议>

## 第二部分：总体统计
-应交人数：<整数>
-已交人数：<整数>
-未交人数：<整数>

## 第三部分：分析结果

### <结果编号>

-结果类别：<工作总结／工作进展／人员建议／idea／重点谈话／公共技术／公共培训>
-主题或对象：<名称>
-涉及人员及部门：<人员、部门编号>
-具体内容：<按相应Skill规定的字段展开>
-依据与来源：<原记录编号列表>

```

个人日志尚未接受评价时，评价填写“待评价”；未交日志只保留名单中的身份和提交状态，不虚构原文、成果或肯定之处。S04—S09 的逐人记录可以用来源编号及可读取的位置引用本次输入，避免每份阶段报告重复复制全部日志。

统计按名单与实际文件计算，不能把搜索未命中等同于未交。单日人数按人员编号去重；跨日统计区分去重人数与按人按日计算的人次，不把多天人数直接相加冒充人数。

## 六、Skill 归属部门与版本配置

### 1. 部门归属

S01—S09 都是部门可以配置和使用的 Skill 类型。每个实际使用的 Skill 配置必须有所属部门。同一个 Skill 类型可以在多个部门复用，不按人员重新发明 Skill 编号。

团队提供一套可直接使用的默认模板；新部门建立时直接采用默认模板。具体骨干和部长可以在本部门建立自己的修改版本。未修改时使用默认版，不要求先编写提示词才能使用。

团队负责人跨部门运行时也需要绑定一个配置归属部门，暂称“团队管理部门”，只作为配置归属占位，可替换为实际承担管理职责的部门，不增加第五类人员。该配置的使用范围为负责人有权查看的所有部门；归属部门与数据访问范围是两回事。

### 2. 默认版与修改版

| 配置字段 | 说明 |
| --- | --- |
| Skill 编号 | S01—S09，共用的功能类型 |
| 所属部门 | 本配置所属部门编号 |
| 适用人 | 部门默认／具体骨干／具体部长／团队负责人 |
| 配置版本、基于版本 | 本次版本及其基于的默认版本 |
| 可修改内容 | 评价侧重点、分析规则、用语、提示词、领域示例；S01可调整日志整理提示 |
| 统一约定 | 保留公共字段、输出结构及来源引用；分析Skill不接管时间筛选 |
| 生效范围 | 本部门或本人管理范围；负责人配置可为全团队 |
| 维护人 | 负责该版本的人 |

运行时优先采用该使用者在该部门的指定版本；没有个人版则使用部门默认版；没有部门修改则使用团队默认模板。修改个人版本不自动影响其他人或部门。

同一教师负责多个部门时，各部门配置独立选择。默认模板升级不静默覆盖已有修改版。每份结果记录实际使用的部门、Skill 和版本，便于知道结论按哪套规则生成。

允许各部门调整分析方法，但用于全团队比较的报告采用团队负责人指定的统一版本，不能将不同评价标准的结果直接视为可比评分。修改版需保持输入输出字段有效，且不能通过提示词扩大人员权限。

## 七、程序筛选、Skill 分析与 Agent 调度

### 1. 分工

| 执行者 | 做什么 | 不承担什么 |
| --- | --- | --- |
| 程序 | 根据人员权限、部门、角色、起止日期读取完整记录；排序、去重、核算提交数量，输出筛选结果 | 不替代人判断工作质量、潜力或思想情况 |
| Skill | 对准备好的记录进行整理、评价、汇总或专项分析 | S04—S09不自行查询全库、决定时间范围或再次按日期筛选 |
| Agent | 读取定时配置，先调用程序准备材料，再调用相应部门的Skill版本，保存结果并交给确认人 | 不自行改变权限或把人员建议直接执行成人员变动 |
| 人 | 补充原始事实，确认或修改结果，组织例会，决定人员、经费和资源安排 | 无需重复人工筛选文件和统计数量 |

S02 所需“前一日”材料同样由程序准备；S03 的合并、排序、去重、计数由程序完成，Skill 主要整理整体工作总结。这些程序属于后续 Skill／Agent 的辅助脚本，不开发 Web 系统。

### 2. 分析 Skill 的输入边界

用户或定时配置给程序“部门范围＋起止日期”。程序输出“已筛选记录集合＋材料范围说明”，再交给 S04—S09。

材料范围说明记录实际覆盖的起止日期、部门和完整性情况，供 Skill 正确描述结论范围；它不是让 Skill 再筛一次的查询指令。相同范围的筛选结果可供多个分析 Skill 复用。

例如，程序先选出某部门9月1日至9月30日的全部有效检查记录；S05只分析这些记录并生成人员建议，S06只分析同一批记录并提取idea，S07只分析同一批记录并筛查谈话线索。

无记录时返回“本范围内暂无可分析材料”，不编造结论。输入材料缺失时提示对应负责人处理，不把缺失部分默认为无问题或未交。

### 3. 周期与确认

| 工作 | 周期 | 默认材料范围 |
| --- | --- | --- |
| 基层、骨干日志 | 每日 | 当日本人工作 |
| 部长日志 | 每周 | 本周本人工作 |
| S02检查、S03汇总 | 每日 | 前一日对应材料 |
| S04阶段进展 | 每三天一次 | 最近三个完整自然日 |
| S05、S06、S07 | 每月一次 | 上一自然月 |
| S08、S09 | 每周一次 | 上一完整自然周 |

时区为北京时间；具体运行时刻、三天周期起算日、周报提交时刻及月度执行日由配置确定。以上材料范围为默认值，可在程序调度配置中修改，不改分析Skill本身。

结果先标记待确认；确认人可直接确认或修改后确认。下一级正式汇总使用已确认材料。日报检查、部门汇总、团队汇总按依赖顺序衔接，不能仅按固定时刻跳过缺失输入。

月度谈话筛查与实际例会频率分开：当前暂沿用每月自动筛查、每周组织例会的安排；需要新名单时可手动运行。具体频率仍可继续调整。

部长周日志目前保留为独立输出，未增加新的检查职责。公共技术与培训分析输出先形成建议，确认入库时再按公共技术库、公共课程库各自的条目结构保存。
