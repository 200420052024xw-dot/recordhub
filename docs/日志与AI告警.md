# 日志与 AI 告警

## 查看与导出

终端显示精简中文说明、事件编号和执行编号。stderr 用于运行日志，stdout 保留给 CLI 的 JSON 输出。

日志文件为 `logs/recordhub.<进程号>.<随机编号>.jsonl`，每行是完整 JSON 事件。不同进程使用不同文件，并用操作系统锁避免清理其他进程正在写入的文件。仍只运行一个业务服务实例，防止重复调度；CLI 可独立运行。

```bash
recordhub diagnostics --event-id <事件编号>
recordhub diagnostics --execution-id <执行编号>
# 没有安装命令行入口时：
python main.py diagnostics --execution-id <执行编号>
```

导出包括关联日志、阶段结果、异常链、版本和代码位置。查询不会初始化飞书客户端、启动后台告警或运行工作流；找不到资料时返回 `not_found`，退出码为 1。HTTP 响应的 `X-RecordHub-Execution-ID` 可用于关联服务端记录。此工具只处理技术运行日志，不查询或清理学生业务日志。

## 三天保留与容量

`RECORDHUB_LOG_RETENTION_DAYS=3` 是默认配置，按记录时间计算 72 小时。服务启动及每小时清理一次，超过期限的记录在下一次清理删除。清理覆盖运行日志、旧文本日志、SQLite 中的事故证据、模型分析和待发报错原文；复制资料、生成汇总或轮转文件不会延长证据期限。业务快照及原有通知台账继续使用各自的业务保留规则。

日志每天轮转，或达到 `RECORDHUB_LOG_MAX_BYTES=20971520`（20 MiB）时提前轮转。目录默认上限 `RECORDHUB_LOG_DIRECTORY_MAX_BYTES=1073741824`（1 GiB），超限优先删除最旧且未被其他进程占用的日志。容量不足时，资料可能早于三天被清理。服务停止期间没有后台清理，下一次启动补做清理。

## 通知规则

- 自动重试过程和成功降级保留证据，不因 WARNING 带堆栈就发通知。已改造的底层接口错误由业务边界统一通知；未分类第三方 ERROR/CRITICAL 保留兜底。
- 普通故障最多等待 `RECORDHUB_ALERT_ANALYSIS_TIMEOUT_SECONDS=15` 秒，包含分析排队时间。模型沿用 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，每轮最多请求一次，不执行业务 Prompt 的重试。
- 分析成功发送中文影响说明、可能原因、排查建议、不确定项及真实证据编号。结构错误、空输出、虚构证据、接口失败和超时均回退到原始报错；只做必要脱敏，不使用模型改写兜底正文。超长原文分段完整发送。
- 启动失败、端口监听失败、飞书关键线程退出及 CRITICAL 立即发送原文，分析成功后补充一次，失败不再重复发送。
- 同类问题按业务范围、阶段、异常及接口错误码归并。首次通知，重复次数持续累计；持续发生时每 `RECORDHUB_ALERT_SUMMARY_MINUTES=360` 分钟最多汇总一次。只有对应范围明确成功才通知恢复，复发作为新事故。
- 设置 `RECORDHUB_ALERT_AI_ENABLED=false` 可直接发送原文。连续三次分析失败后暂停分析五分钟，期间直接发送原文。

技术资料和通知保留姓名，隐藏配置密钥、Token、手机号、OpenID。不额外记录或提交完整学生日志、模型输入输出；模型校验失败的输入值也不写入异常详情。模型没有执行命令、重跑任务或宣布恢复的权限。

## 发送状态与退出

事故及待发通知位于 `<RECORDHUB_STATE_DIR>/admin_alerts.sqlite3`，使用事务防止 CLI 与服务重复领取同一个发送任务。分析状态也持久化，进程中断后已尝试的分析不会重新请求，改用原文。

飞书发送使用稳定 UUID。明确拒绝后一分钟再试；响应丢失等结果不明时，仅在首次该分段尝试的一小时内使用相同 UUID 重试。超过窗口后停止自动重发，状态标记为 `unknown`，需要管理员在飞书核对；本地 `admin_alert_delivery_failed` 日志及 outbox 的 `error` 字段保留线索。

正常退出最多等待约 20 秒发送当前通知；剩余状态保存在磁盘，下次启动恢复，超过保留期限的通知不再补发。SIGKILL、断电和进程完全退出后的事故依赖进程外监测，应用内告警不能承担进程存活监测。

## 宝塔部署检查

1. 把工作目录设为项目根目录；`RECORDHUB_LOG_DIR` 和 `RECORDHUB_STATE_DIR` 建议使用绝对路径，运行账号需要读写权限。更新代码时保留这两个目录。
2. 设置 `RECORDHUB_ADMIN_OPEN_ID`，检查飞书应用的消息权限。告警使用独立消息客户端，不走业务收件人覆盖。
3. 按 `.env.example` 核对日志配置。已有 `.env` 中显式设置的保留天数会覆盖三天默认值，应设为 `RECORDHUB_LOG_RETENTION_DAYS=3`。
4. 发布时将 `RECORDHUB_RELEASE` 填为 commit 或发布编号。只启动一个业务服务进程。
5. 进程守护的正常退出等待时间至少设为 25 秒，再执行强制终止。配置重启退避，避免端口冲突导致重启风暴。
6. 在宝塔或独立监测中检查进程、健康接口、磁盘容量、重启次数及任务是否按期完成。飞书或服务器网络故障时，飞书告警也可能无法送达。

离线回归命令：`python -m unittest discover -s tests`。测试使用临时目录、模拟模型和模拟飞书，不发送真实消息。
