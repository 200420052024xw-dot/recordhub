# 项目目录说明

唯一上游仓库为 <https://github.com/200420052024xw-dot/recordhub.git>，本地项目根目录为 `F:\RecordHub`。在 IDE 中打开这个目录，终端也在这个目录运行 `main.py`。代码包名 `recordhub` 不要求再创建一个同名的项目目录；Python 包的位置由根目录 `pyproject.toml` 定义。

```text
RecordHub/
├── main.py                 命令行和服务启动入口
├── pyproject.toml          Python 打包与依赖配置
├── requirements.txt        依赖清单
├── config/                 环境参数、日程和飞书表映射
├── service/                HTTP API、定时任务、事件监听和管理员告警
├── src/
│   ├── workflow1/          每日日志评价与日报
│   └── workflow2/          阶段、月度和周度分析
├── data/                   组织信息、日志读取和状态存储代码
│   └── state/              本地运行状态，Git 忽略
├── tool/                   飞书、HTTP、发送台账和日志诊断
├── llm/                    AI 客户端与 Prompt 执行
├── schema/                 共用数据模型
├── prompts/                Prompt 文件
├── scripts/                运维、数据录入和模拟脚本
├── tests/                  自动化测试
├── docs/                   文档与参考资料
├── logs/                   运行日志，Git 忽略
├── local-backups/          本地恢复备份，Git 忽略
├── .env                    本机凭据与配置，Git 忽略
├── .venv/                  本机 Python 环境，Git 忽略
└── .idea/                  本机 IDE 配置，Git 忽略
```

## 为什么原来有两份项目

2026-10-09 核对发现，根目录与原 `recordhub/` 子目录都配置了相同的 GitHub 远程地址，但它们是两份独立的 Git 工作区。根目录提交为 `340ce40`，与核对时远程 `main` 一致；子目录停在更早的 `ec47269`，该提交是根目录提交的祖先。子目录工作区干净，没有根目录缺少的文件。

因此以根目录继续开发，保留根目录所有未提交改动。旧子目录连同隐藏的 `.git` 历史压缩到：

`local-backups/recordhub-legacy-20261009-202646.zip`

备份共 121 个文件，逐文件校验 SHA-256 与原目录一致。旁边的 `.manifest.json` 记录压缩包 SHA-256、文件数量和原提交。IDE 已移除子目录的 Git 映射，并排除备份目录索引。

备份仅用于本地恢复，不提交到 Git。需要恢复旧副本时，先校验压缩包，再解压到另一个独立目录；不要解压回当前项目根目录。此整理不重置根目录 Git、不覆盖 `.env`、不修改实际运行状态。
