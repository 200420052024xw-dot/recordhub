# 提交日志前展示历史评价

WorkBuddy 在确认学生身份、确认日志提交窗口开放后，先展示本人前天日志的最终评价，再收集今天的日志。无需确认已读；没有日志、评价尚未就绪或查询失败时，提示后继续提交。

例如北京时间 2026-10-26 提交时，取 2026-10-24 的日志评价，即昨天完成评价的那份。晚于当天评价截止时间提交也仍取前天，不切换到昨天。

## API

`POST /workbuddy/v1/work-logs/previous-evaluation`

使用现有 `RECORDHUB_WORKBUDDY_TOKEN` 作为 Bearer Token，无需查询 Token。只接受已确认身份的 `person_id`，不接受日期、范围或目标条件。仅支持基层学生和骨干学生。

```json
{"person_id":"S003"}
```

有最终评价时：

```json
{
  "code": "OK",
  "log_date": "2026-10-24",
  "status": "ready",
  "evaluation": {
    "positive": "任务进展描述清晰",
    "improvement": "建议说明遇到的具体困难",
    "source": "人工"
  }
}
```

| 结果 | 含义 | WorkBuddy 行为 |
|---|---|---|
| `OK` / `ready` | 有完整的最终评价，来源为 `人工` 或 `AI` | 展示 `log_date`、肯定和改进建议，然后继续 |
| `OK` / `no_log` | 当天没有该学生的日志 | 说明没有记录，然后继续 |
| `OK` / `pending` | 有日志，但尚无完整的最终评价 | 说明暂无最终评价，然后继续 |
| `OUT_OF_SCOPE` | 人员不存在或未启用 | 说明暂时无法获取历史评价，然后继续；提交接口仍负责提交身份校验 |
| `ROLE_NOT_ALLOWED` | 不支持该角色 | 同上 |
| `QUERY_FAILED` | 读取异常 | 提示暂时获取失败，然后继续 |

`no_log` 和 `pending` 的 `evaluation` 均为 `null`，仍包含 `log_date`。业务结果均为 HTTP 200。401 表示 Token 错误，503 表示服务或 Token 未配置，422 表示请求格式错误；入口遇到这些错误也提示后继续今天的日志流程，不反复重试评价请求。

最终评价复用现有查询读取逻辑：优先读取已完成快照，缺失时从飞书重建；只返回已确认且肯定、改进两栏完整的内容，不返回 AI 初评或未定稿批改。本接口不写入评价、已读记录或日志。

## 入口接入

在日志提交技能的身份确认和提交窗口检查之后、请学生口述日志之前调用本接口，一次提交对话展示一次。使用本次身份查询返回的 `person_id`，不得从日志内容里的其他姓名切换身份。日期照返回值展示，不在入口自行计算。

只忠实转述历史评价，不重新评价学生的工作，也不把历史评价并入今天的日志内容。展示后无需已读确认；继续使用原有的四栏整理、学生确认及日志提交步骤。学生已经给出的内容要保留，后续修改或提交重试不重复展示评价。

本地交付模板 `docs/skill-template/SKILL.md` 已同步此流程。该目录按项目现有规则不进入版本库；分发时需把新版模板同步到学生安装的 WorkBuddy 技能。后端部署与技能同步完成后，此功能才在学生入口生效。
