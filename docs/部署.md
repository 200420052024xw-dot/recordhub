# 宝塔部署与迁移

本次新服务器约定：应用目录 `/www/wwwroot/recordhub`，Python 3.11，应用端口 **8100**，单进程。子域名待提供。宝塔管理 Nginx 站点、反向代理和 HTTPS；在宝塔终端安装本仓库的 systemd unit 托管应用。

访问链路：`HTTPS 子域名:443 → 宝塔 Nginx → 127.0.0.1:8100`。8100 是应用内部端口，不需要加入服务器安全组或宝塔防火墙的公网放行规则。域名尚未提供时，可在服务器终端通过本机地址验收。

## 部署文件

| 文件 | 用途 |
| --- | --- |
| `deploy/recordhub.service` | www 用户、8100、单进程、失败退避与重启上限 |
| `deploy/nginx-proxy.conf` | 宝塔站点 server 块内使用的代理片段 |
| `deploy/constraints.txt` | 固定本次本地测试所用运行依赖版本 |
| `scripts/deployment_check.py` | 无联网、无告警、无任务调度的部署预检 |
| `scripts/recordhub-port-check.sh` | Linux 启动前检查端口占用，缺少 ss 也会失败 |

不要再给同一应用创建宝塔 Python 项目守护、Supervisor、Gunicorn 多 worker、定时拉起或手工后台进程。多个端口上的进程也可能执行相同任务；端口检查无法替代单实例管理。旧服务曾因端口冲突和无限重启产生大量告警，新 unit 已内置 5 分钟最多启动 5 次、每次间隔 10 秒。

## 1. 准备服务器和代码

在宝塔安装 Nginx，并准备 Python 3.11（包含 venv/pip）、systemd、ss（iproute2/iproute）。确认 `www` 用户及用户组存在。命令中的 `python3.11` 如与宝塔安装路径不同，替换为面板提供的 Python 绝对路径。

上传经过审核的项目源码到 `/www/wwwroot/recordhub`，包括 `config/`、`prompts/`、`src/`、`service/`、`scripts/`、`deploy/`、`pyproject.toml` 等。当前工作区含未提交业务改动，仅拉取远程仓库无法得到这些改动，发布前要确认完整发布版本并记录编号。

不要上传 Windows `.venv/`、`.idea/`、`__pycache__/` 或本地模拟用 `data/state/`；Linux 虚拟环境必须重建。不能仅上传 wheel：当前配置和 Prompt 依赖源码目录下的外部文件。

```bash
cd /www/wwwroot/recordhub
python3.11 -m venv .venv
.venv/bin/python -m pip install -c deploy/constraints.txt -e .
.venv/bin/python -m pip check
mkdir -p data/state logs
```

约束文件来自 Windows/Python 3.11 已通过测试的依赖版本，并非带哈希的跨平台锁文件。仍须在目标 Linux 上确认依赖安装成功并执行测试；不要复制本地环境中无关的 openai 等依赖。

## 2. 配置与离线预检

新安装时从 `.env.example` 创建 `.env` 并填写密钥；迁移已有服务时安全传输旧服务 `.env`，保留现用 Token。不要用模板覆盖旧配置。现有 `config/tables.toml` 包含真实表映射，确认目标仍使用相同飞书租户和表，再保留；新租户从 `config/tables.example.toml` 创建并填写。

核对：

- 飞书 App ID/Secret、多维表 App Token、DeepSeek Key、归档父目录 Token。
- 管理员 OpenID，以及管理员、提交、查询、批改和确认 Webhook 的 Token。当前按用户要求五项共用同一个带指定前缀和随机后缀的值，持有该值可访问全部这些接口。同步更新调用端的 Token。
- 确认 Webhook Token 允许留空，此时接口返回 503；若使用这个入口必须填写并同步调用端。
- `RECORDHUB_STATE_DIR=data/state`、`RECORDHUB_LOG_DIR=logs`，或目标服务器上的有效绝对路径；移除旧 `/root/...` 或 Windows 路径。
- 正式切换时 `RECORDHUB_SIMULATION_MODE=false`、`RECORDHUB_SCHEDULER_ENABLED=true`、`RECORDHUB_EVENT_STREAM_ENABLED=true`。Workflow2 沿用旧服务开关，避免无意启用或关闭周期任务。
- `RECORDHUB_RELEASE` 填本次发布编号；`config/schedules.toml` 的时区应为 `Asia/Shanghai`，确认服务器时钟准确。
- 飞书通讯录、表读写、文档及消息权限，以及对应审核表单链接。离线检查不验证远程权限和真实字段类型。

Token 可以自行设置，生产预检要求至少 32 个字符且无首尾空白；建议使用随机值。可在服务器运行 `.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))'`，再将同一个值填写到五项配置。不要将实际密钥粘入部署报告或提交 Git。修改后重启服务并同步所有调用端。

配置完成后设置访问权限，再以服务用户检查，避免 root 检查通过、www 运行失败：

```bash
cd /www/wwwroot/recordhub
chown -R www:www /www/wwwroot/recordhub
chmod 600 .env
sudo -u www .venv/bin/python scripts/deployment_check.py --production --check-port
sudo -u www .venv/bin/python -m pip check
sudo -u www .venv/bin/python -m unittest discover -s tests -q
```

没有 sudo 的服务器可使用等效的用户切换命令。预检不会创建应用运行时，不会刷新飞书、发送通知、运行工作流或清理业务状态；只临时写入并删除目录权限探针。`--check-port` 只能在服务尚未启动时运行，生产运行中检查去掉此参数。`passed` 只表示离线项目通过，仍需逐条处理 warnings。

## 3. 迁移生产状态与单实例切换

旧服务在线时，新服务器只做安装、离线检查和测试。不要连接相同生产飞书应用启动第二个实例；关闭定时调度仍可能建立飞书事件长连接。

正式切换顺序：

1. 备份旧服务器的代码版本、`.env`、`config/tables.toml`、`config/schedules.toml` 和实际 `RECORDHUB_STATE_DIR` 全目录。日志可另行备份用于排障。
2. 暂停客户端写入或安排维护窗口。在旧服务器停止旧应用托管服务（旧环境如使用 systemd：`systemctl stop recordhub.service`），确认旧进程退出，包括其他守护器或手工启动的残留实例。
3. 停止后再复制最终状态到新服务器。完整保留快照、组织缓存、WorkBuddy 暂存、批改、通知去重、任务重试、告警状态和 Workflow2 启用日期。不要只挑当天 JSON；不要用本地模拟状态替换生产状态。复制走受保护的 SSH/SFTP 通道。
4. 修正新目录所有者，再运行预检。旧服务在整个切换期间保持停止，验收成功后关闭旧托管器的自动启动，保留旧机备份。
5. 按下一节启动新服务，完成本机健康检查。域名就绪后配置代理并切换客户端基础地址，原有接口路径及 Token 保持一致，随后恢复客户端写入。

如配置使用自定义状态目录，应按其真实路径复制并修改 unit/权限；不要默认旧服务器状态就在项目的 `data/state`。

## 4. 启动和验收

在宝塔终端安装 unit。若旧环境有 `recordhub.service.d/*.conf` drop-in，先检查并清理不适用于新目录、端口或退避参数的覆盖配置。

```bash
cd /www/wwwroot/recordhub
cp deploy/recordhub.service /etc/systemd/system/recordhub.service
systemctl daemon-reload
systemctl cat recordhub.service
systemctl enable --now recordhub.service
systemctl status recordhub.service --no-pager
ss -lptn 'sport = :8100'
curl --fail --show-error http://127.0.0.1:8100/health/live
curl --fail --show-error http://127.0.0.1:8100/health/ready
journalctl -u recordhub.service -n 50 --no-pager
```

应只有一个应用进程监听 `127.0.0.1:8100`。检查日志中的组织缓存刷新、调度器和飞书长连接；健康接口只说明 HTTP 启动完成，不能证明飞书/DeepSeek 权限和所有工作流正常。尤其组织刷新失败时可能回退到旧缓存，需要查日志确认。

服务器须能出站访问飞书 HTTPS/WebSocket、DeepSeek HTTPS 和依赖源。飞书当前使用长连接，不需要 Nginx 转发这个出站连接的 WebSocket 升级头。业务冒烟验收应使用测试账号，核对鉴权和数据读取；写入飞书、生成报告、通知和付费模型调用留到正式联调窗口执行。

日常只通过 `systemctl restart recordhub.service` 重启。触发启动上限后先查 `journalctl`，解决原因，再执行 `systemctl reset-failed recordhub.service` 和 `systemctl start recordhub.service`。

## 5. 子域名就绪后配置宝塔

在宝塔创建绑定所给子域名的站点，站点目录使用单独空目录，例如 `/www/wwwroot/recordhub-site`。添加指向 `http://127.0.0.1:8100` 的反向代理，保留全部原始路径和 Authorization 请求头，不加子路径前缀、不启用代理缓存。

可将 `deploy/nginx-proxy.conf` 片段放入该站点已有的 `server {}` 内；若宝塔已生成 `location /`，编辑或替换该块，避免重复。保留宝塔的证书验证配置，不替换整个站点配置。在面板检查 Nginx 配置并重载。

先配置 DNS A/AAAA 指向服务器（仅在服务器支持 IPv6 时添加 AAAA），等待解析正确，再在宝塔申请证书并开启强制 HTTPS。安全组和宝塔防火墙放行 80/443；8100 保持本机监听。HTTP 尚未切换 HTTPS 时不要通过公网传送 Bearer Token。

验收：访问 `https://实际子域名/health/live` 和 `/health/ready` 返回预期 JSON；确认无 Token 的受保护接口返回 401、关闭的接口返回 503；使用共用 Token 验证客户端真实请求。API 文档默认有 `/docs`、`/redoc`、`/openapi.json`，若不希望公网展示，可在站点配置单独限制访问。

## 6. 回滚

新实例未写入生产数据时：停止新实例，确认退出，恢复旧客户端地址及代理/DNS，启动旧服务并检查健康。DNS 切换不保证立即覆盖所有客户端，维护窗口内确认客户端入口统一后再恢复写入。

新实例已接收提交、批改、运行任务或发送通知时：先暂停写入并停止新实例，备份其最新状态；核对期间的飞书写入与通知去重，再将兼容的最新状态迁回旧服务。不要直接恢复旧快照后重跑日期，否则可能丢失暂存数据或产生重复记录、重复通知。任何时候只保留一台服务器运行生产应用。
