# 对话入口功能开发流程

适用场景:给 WorkBuddy 这类对话入口加一个新功能(如"提交工作日志"),入口负责跟人对话,我们的服务负责存数据和写回飞书。

以"提交工作日志"为范例,全程六个阶段。**最容易跳过、也最该花时间的是阶段 0。**

## 分工

| 谁 | 做什么 |
|---|---|
| 同学 | 阶段 0 的语义梳理、阶段 2 的接口契约、阶段 4 的入口话术、阶段 5 的自测 |
| 我们 | 阶段 1 的数据落点、阶段 3 的后端实现、阶段 5 的复验 |

只有阶段 3 需要动后端代码,而且是我们写。同学的产出全是文档 + 测试用例。

---

## 阶段 0:先定语义(不写任何东西)

一次一个功能,把下面每条都问一遍,并且**每条都要有人拍板**。产出:一页纸的"已定语义",写明哪些约定不再讨论。

- 谁用?触发语有哪些?
- **身份怎么认定?**姓名、手机号、还是别的?
- 什么时候能提交?**"今天"是哪一天**(服务器时间?北京时间?)
- 跨零点怎么办?上午来交算哪天?
- 允不允许补交?提交窗口几点到几点?
- 同一个人交多次怎么办?**以最后一次为准 / 覆盖 / 追加**?
- 能不能改、能不能删?**没有修改入口的话,"改"等价于再交一次**
- 内容由谁整理?入口侧的模型整理,还是后端?
- 提交成功之后,下游什么时候看到?失败了谁知道?
- 给用户的话术边界:哪些话不能说?

范例的答案(可直接对照):窗口 12:00–23:50、**不允许补交**、身份只输姓名、一人一天一条、以最后一次为准、没有修改入口。

> 定"不允许补交"这一条,直接砍掉了后端一半的分支(不用管滞期、不用重算历史)。**语义一旦收紧,代码就变简单;语义含糊,后面到处打补丁。**

## 阶段 1:数据落在哪

1. **先翻现有的飞书表**,有没有能直接用的字段。日志用的是表里本来就有的「工作进展/工作困难/心得反思/其他」四栏,**不需要新建表、不需要新建字段**。
2. **不要直接写飞书**:飞书写失败就丢数据,而且怕限流、怕慢。先落本地暂存。
3. 暂存只保留"**还没进表**"的数据,写回成功后删掉,所以目录始终很小。
4. 命名:`<姓名>.json`,一人一个文件。重复提交覆盖同一个文件——覆盖本身就表达了"以最后一次为准"。
5. 日期放在**文件内容**里,不放在文件名里。

## 阶段 2:先写契约,评审通过再写话术

一页纸,写清四样:端点、请求字段、返回的错误码、重复提交会怎样。

铁律:

- **契约里不许出现** `table_id`、`field_id`、`record_id`、`ou_xxx`、列名。
- 输入只写**业务语义**(如"日志内容"),不要写成飞书字段的形状。

评审只问三件事:

1. 输入是不是纯业务语义?
2. 同一笔重复提交两次,会怎样?
3. 失败码够不够用——每个失败码能不能对应一句对人有用的话?

## 阶段 3:后端实现

- **收数据与写回分开**。请求路径上只做:校验 → 写暂存 → 返回。不碰飞书、不调模型(所以是毫秒级返回)。
- **写回挂在既有工作流的前置步骤**,失败就让当日工作流 `FAILED`(可重跑)。**绝不允许"写回失败还继续跑下游"**——那会把交了数据的人判成没交。
- **独立 token**。入口的 token 拿不到 `/admin/*` 权限,让"入口不许碰管理接口"从口头纪律变成技术强制。
- **业务失败一律返回 HTTP 200**,失败原因放返回体的 `code` 字段。因为对面是模型在判断:它看到 404/500 会理解成"接口坏了,重试一下";看到 `NO_PERSON` 才知道该说"没找到你的信息"。
- 幂等:业务键记在状态文件里,重跑不重复建行;键丢了但行已存在的,按(姓名 + 提交时间)认领。

## 阶段 4:写入口话术

交付给对话入口的就三样:引导话术、接口说明、红线。结构固定:

1. **什么时候用**——列出用户真实会说的几句话
2. **要采集什么**——字段 + 缺了怎么问;明确"不要问"哪些(后端能自己算的都不问)
3. **怎么调**——哪个端点、发什么
4. **按 code 怎么回**——严格照 code 说话,不自己解释原因
5. **红线**——不许出现表名列名字段 ID;不写死网址(链接由接口给);不承诺"已保存/已确认",只说"已收到,次日凌晨归档";不替人确认;不拿全员名单自己认身份

## 阶段 5:自测 → 复验

自测用例至少覆盖:身份查不到 / 重名 / 空内容 / 窗口外 / 重复提交 / 写回后重跑。

复验的硬项只有两条,但必须验:

- 同一个人交三次,表里**只有一行**,内容是最后一次
- **故意让写回失败**,当日不能产生"未交"的错标

## 常见返工原因

| 返工现象 | 根因 |
|---|---|
| 后面到处打补丁 | 阶段 0 没定"能不能改/能不能补交" |
| 表改一列,所有入口崩了 | 契约或话术里写了字段名 |
| 换个人就认不出身份 | 拿 `open_id` 当身份键(它按应用隔离,实测踩过) |
| 入口只能说"失败了" | 失败码只有成功/失败,没有可对应用户话术的区分 |
| 交了的人被记成没交 | 写回失败后还照常跑下游 |
| 学生以为日志已经进表 | 话术说了"已保存"而不是"已收到,次日归档" |
