# RecordHub 三层整理进度

> 目标：把整个项目拆成三层——**技术底座**（零业务）、**基础服务**（业务无关但带领域概念，所有工作流共用）、**Workflow1 专属**。终态布局 `src/recordhub/{core,domain,workflows}`，按"一个文件夹一个文件夹"推进，每站全量测试兜底。

## 归属判据（2026-10-04 定案）

**W1 专属 = 只有 W1 用（含未实现的 S04–S09）。** S05/S06/S07 的输入是"程序已筛选的本部门学生检查记录"，所以：评价记录数据、检查记录表（`check_details`）、部门/团队分析表、云文档归档、管理员异常通知、LLM 并发/重试默认值，全部属于共用，不是 W1 的。数据共用 ≠ 代码共用：评价表的**写回适配器**、问卷的**三元匹配**、三级**文档格式**只有 W1 的代码在用，这些才是 W1 专属。

## 状态存储布局（用户定稿）

```
data/state/
  organization.json     ← 人员+部门缓存，全系统共用一份
  workflow1/
    2026-10-04.json     ← 一天一个 run 文件，按工作流分目录（拆除了 S04 上线同日互覆的雷）
  workflow2/            ← 预留，暂不讨论
```

旧布局（`workflows/*.json` 平铺、`cache/organization.json`）在服务启动构造 `FileStateStore` 时**自动无损迁移**。2026-10-04 已对实际 `data/state` 执行迁移：`organization.json` 与 `workflow1/2026-10-04.json` 均已就位；缓存、run 和快照重新读取成功，旧空目录已移除。

### 第二站：data/（✅ 45/45 绿，迁移副本验证通过）

- **底座**：飞书记录解析函数公开化为 `tool/bitable_fields.py`（`record_fields/scalar/references/alias_index/resolve_reference/field_datetime/field_boolean/display_name/SHANGHAI`），终结跨包私有函数引用；`FileStateStore` 引擎不再 import `DailySnapshot`——`snapshot_model` 改由装配层注入，引擎同时接受 `workflow_type` 并实现上面的目录布局。
- **基础服务（留在 data/）**：`OrganizationRepository`（手机号换 OpenID、组织异常校验）、`OrganizationCache`（持久化+人员 CRUD）、`LogRepository`（当日取数、同人取最后）。
- **W1 专属搬出**：`data/snapshot.py → src/workflow1/snapshot.py`、`data/workflow1_evaluations.py → src/workflow1/evaluations.py`、`data/workflow1_reports.py → src/workflow1/reports.py`（git mv 保历史）。

### llm/ 归属复核（✅ 47/47 绿，配置检查通过）

- `DeepSeekClient` 保持技术底座职责；`PromptService` 只接收提示词代码、文本和输入输出模型，不再依赖限定 `LOG` 的 `schema.PromptConfig`。
- LLM 执行错误移至 `llm/errors.py`，不再继承 W1 的 `WorkflowError`；W1 自己读取 `prompts/S01.txt` 并传入服务。
- `schema.PromptConfig` 当前已无调用，已在 schema/ 站清理；`tool/infrastructure.py` 仍待装配层归属复核。

### schema/（✅ 47/47 绿，配置检查通过）

- `schema/base.py` 放 `StrictModel/TableDefinition/JsonDict`；`schema/domain.py` 放组织、日志、评价、云对象、表配置和通用 `WorkflowRun`；`src/workflow1/models.py` 放 W1 阶段机、逐日志 Prompt、评价进度、每日快照和问卷事件模型。
- `schema/__init__.py` 只导出共用模型，生产代码和测试里的 W1 模型引用均改为 `workflow1.models`。已无调用的 `PromptConfig` 删除。
- `WorkflowRun.status` 存通用字符串；`FileStateStore` 不再 import W1 的 `WorkflowStatus`，现有状态 JSON 的字段和值保持不变。

### service/（✅ 50/50 绿，配置检查通过）

- `Runtime.workflows` 注册每个工作流的实例、状态仓库、事件处理函数和截止时间；W1 当前注册为 `workflow1_daily`，CLI 显式选取该工作流。
- `bitable_events.py` 按表 ID 查处理函数，不再 import `Workflow1`；回调只入队，工作线程调用对应处理函数。
- `api.py` 保留**全部 HTTP 路由在同一个文件**（用户要求），调度和恢复遍历已注册工作流；新增测试覆盖路由注册、双工作流调度和重复表 ID 防护。

### tool/（✅ 49/49 绿，配置检查通过）

- `http.py`、`feishu.py`、`cloud_docs.py`、`bitable_fields.py`、`errors.py` 只做外部接口与数据解析，继续留在技术底座 `tool/`。
